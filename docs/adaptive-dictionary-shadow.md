# Adaptive dictionary research — isolated trial

Add repository Actions **secrets** (not Variables): OPENROUTER_API_KEY, GEMINI_API_KEY and TAVILY_API_KEY. OpenRouter serves Nemotron 3 Ultra free; the Google key serves Hydrogen and Flash-Lite on the user's free-tier project. No paid-model fallback. Keep Google billing disabled. Disable provider paid top-ups and configure spending controls. GitHub Actions schedules 21:00 and 22:00 UTC; Africa/Cairo local-hour/day guards handle DST and deduplicate nightly attempts. Use Actions > Adaptive Dictionary Research (Shadow) > Run workflow > benchmark first. Choose daily for an immediate full cycle; nightly runs automatically when secrets are present.

Research uses a separate concurrency group and writes only research/shadow-state: research-results/state.json, career-level-dictionary.json, job-family-dictionary.json and report.json. This repo is public: research artifacts contain only public employer listing text and aggregate comparison metrics, never preferences, user records, secrets or emails. The admin UI reads the aggregate report through the existing authenticated admin API on both hosts. No new environment variables on Vercel or Cloudflare. No production classifier or notification code imports the research modules.

Daily research checks configured company pages and a bounded sample of ambiguous catalog jobs. It rotates 16 initial basic Tavily queries/day and reserves up to 8 additional queries for model-requested follow-up research (24/day total, 744/month), and caps both models together at 40 requests/day (account usage outside this workflow is not included). Direct fetches are restricted to configured HTTPS employer hosts and matching shared ATS tenants; blocked or dynamic pages may be unavailable. The same candidate must pass deterministic evidence checks with two distinct models before shadow classification. No automatic promotion to production. Exact quotation and model agreement are not ground truth. Family candidates are scoped to job-content fingerprints, not blanket title expansions. Free endpoints may be unavailable; no paid fallback.

Benchmark mode evaluates both models on an existing limited independent semantic-role reference with expected answers withheld, reports response coverage, also tests explicitly labeled synthetic career-level cases, and tests evidence retrieval on six companies. Benchmark does not change candidate dictionaries. Daily mode measures full catalog differences. The reference is a limited regression benchmark, not a representative estimate of production accuracy. Run the trial for at least 14 days; manually review changes and label a held-out sample of real vacancies across role families and career levels before deciding on production rollout. No activation switch in this release.

Research batches now contain at most two employers and contiguous source excerpts of at most 2,600 characters each. This reduces context pressure but may omit evidence; missing evidence is not treated as a positive result. Provider-specific failures (timeouts, empty content, malformed/truncated JSON, HTTP errors) are reported separately without raw provider error bodies. HTTP 404 disables that model for the remainder of the research phase. Existing daily quotas and shadow-only isolation remain unchanged.

## Split-task architecture v3
Each daily run targets a rotating cohort of up to 10 employers. Career evidence uses up to two live employer excerpts; family uses up to two ambiguous vacancies and actual duties/department only. Each excerpt is bounded to 900 characters. The two free models handle separate tasks and exchange roles on the next opposite-model day over the same cohort. At most 20 initial model calls per day, with remaining capacity for bounded retry; the original hard daily limit of 40 and search limits still apply. Benchmark targets two employers with both models and reserves four calls for the classification benchmark. Provider 429 cools down only the affected model (90–300 seconds), 404 disables it, and timeouts or incomplete output get at most one smaller retry. Empty proposals are valid and no missing evidence is inferred. Coverage is intentionally rotational, not exhaustive nightly. No new runtime dependencies; see current three-model architecture below for keys.

## Append-only protection
Models can propose new entries or independent confirmations only. Existing rule keys, aliases, families, levels and original evidence remain unchanged. Confirmation metadata can grow; candidates can be promoted after two independent models, but existing statuses cannot be downgraded. Contradictory new career aliases are quarantined without replacing old entries. The runner checks persisted dictionaries against state and aborts on a missing or changed historical entry. Benchmarks do not write either dictionary. No production dictionary or classifier is modified.

## Admin conflict review and combined export
The authenticated admin dashboard displays conflicting rules, old alternatives and employer evidence. Approve or reject is stored as an immutable, idempotent admin audit event, shared by both hosts. Combined JSON includes original career taxonomy, exact family title patterns and aliases, raw research rules, effective reviewed shadow dictionaries and review decisions. Approving an alias makes it the effective choice for that employer/alias only; original taxonomy and raw append-only research files remain intact. Reject leaves the existing rule intact. This is a server-side reviewed shadow overlay, not production activation. The isolated nightly runner does not receive database credentials and continues reporting raw shadow comparisons; dashboard export is the authoritative reviewed view. No additional secrets or migration are required.

## Three-model architecture v4 (current)
Gemini 4 Hydrogen and NVIDIA Nemotron 3 Ultra exchange career and family roles nightly and are the only two active voting models. Gemini 3.5 Flash-Lite extracts verified verbatim evidence hints from public documents, retaining the complete bounded source windows to avoid dropping context. Failed extraction falls back to deterministic windows; Lite cannot propose, validate, or promote rules. Primary benchmarks run first. Per-model daily caps: Hydrogen 15, Nemotron 15, Flash-Lite 100 (normally up to 20 prep calls). Persist counters before requests; enforce both Cairo and provider-local day limits, plus model-specific request spacing. No Google Search or Maps grounding; Tavily retains original limits. Google project must remain free-tier; account-wide quotas and provider availability are external. No secrets on deployment platforms. No production matching, admin approval or append-only changes.

## Google research slot failover v5 (current)
Hydrogen, Gemini 3.8 Flash, Gemini 3.6 Flash are ordered endpoints of one Google research slot. The stable Hydrogen identifier represents the slot in dictionary voting (not necessarily the actual endpoint); only agreement with Nemotron can independently confirm new Google proposals. On 503, quota, timeout, malformed response or unavailable endpoint, quarantine that endpoint for the rest of the run and advance to the next available endpoint. Shared Google authentication/permission/billing errors stop the entire Google slot and Lite; no paid fallback. Each endpoint has a 15-call cap per Cairo and Pacific day, with the original shared 40-call hard cap for research including failed attempts. Flash Lite remains preprocessing only; 503 falls back to deterministic original text. The report records the real attempted endpoints and benchmark actual_models, not a false attribution to Hydrogen. Fallback order is a configured preference, not a measured performance ranking. If all Google endpoints fail, Nemotron can produce candidates but cannot independently confirm them. All existing append-only and shadow-only restrictions remain.
