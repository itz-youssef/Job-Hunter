# Botfolio beta
Independent Secret J product, sharing only the existing session and CV API. No legacy Botfolio backend/UI/API reused.
- /botfolio.html: authenticated owner workspace; load existing PDF/DOCX from Neon using existing CV API and parse locally; review text before indexing. Alternative file and manual paste. Up to five bots per owner, isolated snapshots; create private, explicitly publish/unpublish, delete.
- /botfolio-chat.html?id=UUID: public chat; iframe HTML and shareable link. No public raw CV endpoint. Browser-session history only. Public bot metadata is limited to name and headline.
- RAG: 650-character chunks with 70 overlap, multilingual BGE-M3 vectors stored in per-bot JSONB; cosine top four retrieval; GPT-OSS 120B (`openai/gpt-oss-120b`) via Groq's HTTPS chat-completions endpoint; Cloudflare runs BGE-M3 only. Existing indexed CVs need no re-indexing. On Workers use `BOTFOLIO_AI`; on Node/Vercel optionally use restricted `BOTFOLIO_CF_ACCOUNT_ID` and `BOTFOLIO_CF_API_TOKEN` for BGE-M3 REST inference. Supply the existing server-only `GROQ_API_KEY` on each runtime; GitHub Actions secrets are not automatically Vercel variables. Never expose keys to the browser. Prompt grounding reduces, but cannot eliminate, hallucinations or prompt injection.
- Migration 013_botfolio.sql creates only two new tables, RLS enabled, public grants revoked; user deletion cascades. Apply migration to the existing Secret J DB before release.
- Pilot limits: 5 bots/user, 5 indexing attempts/user/day, 15 chats/IP/day, 20 chats/bot/day, 1800 estimated neurons/day across Botfolio. The budget uses conservative estimates and charges before calls; Cloudflare account usage is shared with research, and only the Free plan prevents paid overage. Not live billing telemetry. UTC reset. Limit may constrain chats substantially during pilot; no paid fallback.
- Migration 014 adds only a private singleton rolling-24-hour Groq reservation ledger. Botfolio reserves conservatively by UTF-8 prompt bytes plus overhead and 400 completion tokens, then reconciles with reported total usage on success; failed attempts retain reservations. Botfolio's 35K rolling-token cap plus Research's existing 160K rolling cap leaves 5K estimated headroom within the published 200K free daily token limit. Provider/account rate limits still apply, including 8K TPM and 30 RPM; 429 is handled without fallback or retries. Cloudflare's 1,800 estimated neurons/day is now embeddings only. Existing per-user, bot and IP quotas stay unchanged. A bounded ten-minute exact question/history cache in each process avoids repeating both AI calls for the same published portfolio revision; it is not persistent or approximate semantic caching. Keep provider accounts on free plans; no paid tier is selected by the code.
- No account, job, alert, or research logic changed. Only Botfolio entry points, allowlisted post-login redirect, new API route and binding, and additive migration. CI uses mocked inference; verify actual inference, indexing, publish, iframe and quotas before production claims.
